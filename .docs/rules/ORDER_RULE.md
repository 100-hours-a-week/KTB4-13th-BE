# 주문 도메인 규칙

이 문서는 주문 생성의 업무 정책과 미확정 문서 불일치를 기록합니다. API 경로·HTTP 입력은 코드의 `api/spec`, 테이블 정의는 ERD와 Flyway를 함께 확인합니다.

## 1. 주문 경로와 배송지

- 구매는 활성 장바구니 → 주문 생성 → 결제의 경로만 허용합니다. 상품 상세에서 바로 주문하지 않습니다.
- 주문 요청의 `items[].itemId`는 상품 ID입니다. 각 상품은 요청 회원의 활성 장바구니에 담겨 있어야 합니다.
- 전체 장바구니가 아니라 장바구니에서 선택한 상품만 주문할 수 있습니다.
- 주문 요청에는 배송지 ID가 필수입니다. 회원이 소유한 활성 배송지만 사용할 수 있고 기본 배송지로 대체하지 않습니다.
- 주문을 생성할 때 `order_addresses`에 배송지 스냅샷을 저장합니다. 우편번호는 ERD의 `VARCHAR(5)`를 따릅니다. 기존 주소 우편번호가 5자를 초과하면 주문을 거부하고, 숫자 형식은 추가로 검증하지 않습니다.

## 2. 금액·재고·상태

- 주문상품 단가는 주문 생성 시 서버가 확인한 상품의 현재 `discounted_price`입니다.
- 주문상품 금액은 단가 × 요청 수량이고, 주문 금액은 주문상품 금액의 합입니다. 배송비·쿠폰·포인트는 이 주문 생성 범위에 포함하지 않습니다.
- 요청 상품은 활성 상품·도서여야 하며, 요청 수량이 현재 재고를 넘으면 주문을 거부합니다.
- 주문 생성 중에는 재고를 차감하거나 예약하지 않습니다.
- 새 주문과 주문상품의 초기 상태는 `CREATED`입니다. 결제 승인·취소 상태 전이는 이 API에서 수행하지 않습니다.
- 주문 생성은 배송지 스냅샷, 주문, 주문상품을 한 쓰기 트랜잭션으로 저장합니다. 장바구니 항목을 삭제하거나 수량을 변경하지 않습니다.

## 3. API·인증 계약

- 구현 경로는 요청에 따라 `POST /api/v1/orders/checkout`입니다. Notion API 명세의 `POST /api/v1/orders`와 다르므로 코드의 OpenAPI 계약에 구현 경로를 반영하며 Notion은 수정하지 않습니다.
- Notion의 응답 예시는 `result/data/error` 외피지만, 구현 응답은 프로젝트의 `ApiResponse` 계약을 따릅니다.
- 현재 인증 Resolver가 없으므로 회원 식별은 기존 주소·장바구니 API 규칙대로 임시 `userId` Query Parameter를 사용합니다.
- 장바구니에 없는 상품은 API 명세의 `E3000 PRODUCT_MISMATCH_IN_ORDER`로 거부합니다. 주소 소유권 위반은 프로젝트의 `E403 FORBIDDEN`을 따릅니다.

## 4. 확인 필요

- API 요청 수량이 장바구니에 저장된 수량을 초과할 수 있는지는 명세에 없습니다. 현재 구현은 활성 장바구니에 상품이 있는지 확인하고, 요청 수량은 서버 재고와 비교합니다.
- 같은 상품 ID가 `items`에 여러 번 포함될 때의 병합·거부 정책은 명세에 없습니다. 현재 구현은 입력 행을 각각 주문상품으로 저장하고 재고 확인 시 수량을 합산합니다.
- ERD는 `orders.user_id`를 회원 테이블 FK로 표시하지만 최신 Flyway에는 회원 테이블이 없습니다. 이번 마이그레이션에서는 존재하지 않는 테이블을 참조하는 FK를 만들지 않습니다. 회원 스키마가 추가될 때 연결을 확인해야 합니다.
- ERD에서 `orders.key`는 UNIQUE이면서 NULL 허용입니다. 이번 API는 주문키를 생성해 응답하지만, 마이그레이션은 ERD의 nullable 제약을 유지합니다.
- ERD의 상품 상태 설명은 판매·품절·판매 금지 등을 포함하지만 현재 코드의 상태는 `ACTIVE`·`DELETED`입니다. 이번 구현은 기존 활성 상품 조회와 `stock_quantity` 검증을 사용합니다.
- ERD는 주문 금액 설명에 배송비·포인트를 언급하지만 이번 주문 생성 금액 정책에서는 제외하기로 했습니다. 결제 금액 정책은 결제 기능 정의 시 다시 확인해야 합니다.
- Notion API 오류 목록에는 기존 상품 조회의 `E404 PRODUCT_NOT_FOUND`가 없습니다. 활성 상품·도서 조회 실패는 기존 상품 UseCase 오류를 따르며 API 명세와의 오류 계약은 확인이 필요합니다.
- 제공된 세 번째 도메인 초안은 주문이 아닌 상품 도메인 문서입니다. 별도 주문 도메인 문서도 미완성 템플릿이므로, 여기에 없는 결제 실패 재시도·멱등성·재고 차감 시점 정책은 추가하지 않습니다.
