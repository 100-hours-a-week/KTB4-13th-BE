# ADR-0002: 장바구니 재고 비예약과 요청 시 재고 검증

## 결정

장바구니는 상품 재고를 예약하지 않는다. 상품 추가와 수량 변경 요청은 요청 시점의 가용 재고를 기준으로 검증하며, 요청 수량이 가용 재고를 초과하면 장바구니를 변경하지 않고 실패한다.

장바구니에 저장된 수량은 재고 감소만으로 자동 변경하거나 삭제하지 않는다. 주문 기능이 구현되면 주문 확정 직전에 현재 재고를 다시 검증하고 원자적으로 차감한다. 재고가 부족한 경우에는 수량을 자동 보정하거나 부분 주문하지 않고 주문을 실패시킨다.

## 이유

장바구니에 재고를 예약하면 예약 만료·해제와 동시성 처리가 추가된다. 초기 장바구니에서는 저장된 수량과 실제 재고를 분리하고, 사용자 요청과 주문 확정이라는 필요한 시점에만 재고를 확인하는 편이 단순하다.

재고 감소를 서버가 장바구니 수량에 조용히 반영하면 사용자가 요청하지 않은 상태 변경이 발생한다. 실패 시 기존 장바구니를 유지하고 사용자가 직접 수량을 조정하도록 한다.

## 결과

- 수량 범위 `1~500` 검증과 재고 부족 검증을 별도 규칙으로 유지한다.
- `CartItem.applyQuantity()`는 장바구니 상품 수량의 범위와 상태 전이만 담당한다.
- 상품 추가·수량 변경 UseCase는 상품·재고 Port를 통해 현재 가용 재고를 확인한다.
- 재고 부족 오류는 기존 요청 형식 오류와 구분되는 공개 오류 계약을 사용한다.
- 상품 재고의 소유 시스템, SKU/상품 식별 단위, 가용 재고 산식은 상품·재고 기능과 함께 확정한다.
- 주문 직전 재검증·원자적 차감은 주문 기능의 별도 구현 범위로 다룬다.
- 부분 주문, 백오더, 장바구니 재고 예약은 기본 동작으로 도입하지 않는다.
