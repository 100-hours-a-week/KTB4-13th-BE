# ADR-0004: 상품 인기 지표 스냅샷

## 상태

채택

## 맥락

상품 인기순 정렬은 전체 기간의 결제 상품 수량 합계, 활성 리뷰 수, 활성 리뷰 평균 평점을 사용한다. 요청마다 주문·리뷰 테이블을 상관 집계하면 목록 요청 때마다 같은 통계를 다시 계산한다. 인기순은 결제·재고처럼 즉시 반영이 필요한 계약이 아니므로 집계 시점과 조회 시점 사이의 지연을 허용한다.

## 결정

- 상품별 인기 지표를 `product_popularity_snapshots`에 저장하고 목록 조회에서 사용한다.
- 애플리케이션 준비 직후 한 번 갱신하고, 이후 UTC 기준 매시간 전체 지표를 다시 집계한다.
- 갱신 작업은 트랜잭션으로 실행한다. 실패하면 기존 스냅샷을 유지하고 다음 실행에서 다시 시도한다.
- 여러 애플리케이션 인스턴스의 중복 갱신을 막기 위해 MySQL named lock을 사용한다.
- 공개 API는 기존 `GET /api/v1/items?sort=POPULARITY`를 유지한다.

## 결과

- 인기순 목록 조회는 요청마다 주문·리뷰 집계 서브쿼리를 실행하지 않고 마지막으로 성공한 상품별 스냅샷을 읽는다.
- 정상 갱신 간격은 한 시간이다. 갱신 실패 또는 긴 실행은 값의 지연을 늘릴 수 있고, 커서 페이지 경계는 스냅샷 변경 후 최선 노력으로 유지한다.
- 전체 주문·리뷰 집계를 백그라운드에서 주기적으로 실행하므로 데이터가 커지면 갱신 시간과 DB 부하를 확인해야 한다.
- 즉시 반영, 별도 통계 API, 캐시, 증분 갱신은 이번 v1 범위에 포함하지 않는다.
